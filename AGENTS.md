# Project workflow

- This is a static dashboard. No build step, package installation or backend is required for deployment.
- Serve locally with `python3 -m http.server 8080 --bind 127.0.0.1` from the repository root. Opening `index.html` through `file://` does not support the configuration and GeoJSON fetches.
- Run regression tests with `node --test tests/*.test.js` (Node 18+). Check the shared module with `node --check dashboard-data.js` and whitespace with `git diff --check`.
- Observations page (`index.html`) fragment scroll: `#osservazioni`, `#sensore/{id}`. `applyRoute()` scrolls to the section or sensor card (`#card-{id}`). `#predizioni` redirects to `predizioni.html`. Header nav links Osservazioni ↔ Predizioni (separate page).
- Sticky shrinking header (`#site-header`): compact after ~20px scroll (`is-compact`), height as `--header-h` for sticky map offset and scroll-margin.
- Section `#osservazioni`: map/chain left on desktop, above cards on mobile. Cards ordered by `RenoPredict.rankNodes(config)` (upstream→downstream).
- Section / page Predizioni: one card per downstream (multi-input), min/med/max fork; soft-load `models/transfer-coeffs.json` (direct-horizon delta ridge offline; Cento may be `window_delta_mlp`). Train with `uv sync` then `uv run python tools/fetch-storico.py` + `uv run python tools/fit-transfer.py --data ./storico` (+ optional `uv run python tools/fit-ml-cento.py …`, acceptors valle by default; `--no-acceptors` ablation; `--export-coeffs` opt-in). Offline EnKF spike for Cento: `uv run python tools/fit-enkf-cento.py --data ./storico --out models/enkf-cento-summary.json`. Hybrid volume+DNN: `uv run python tools/fit-hybrid-cento.py …`. Muskingum+GRU / RC+GRU (browser): soft-adopt in `loadCoeffs` only if weights `reliable: true`. Inventory: `uv run python tools/inventory-storico-cento.py`. Backtest: `node tools/backtest.js --every 120 --json models/backtest-summary.json` (updates `reliable` from event skill@120 ≥ 0.10); experimental side-by-side without writes: `--compare-candidates Cento`. Stations with `reliable=false` show no forecast curve.
- Station panel (`#map-container`) tabs: "Catena delle stazioni" (default) and "Mappa". Chain via `updateStationDag()` (inline SVG). Columns `DAG_COLUMN` (0 Reno, 1 centre, 2 Samoggia). Map loads lazily (`mapRequested`). Chips → `#sensore/…`; edges are decorative only (not clickable).
- Browser verification: check widths 360, 390, 768, 1024 and 1440 px, actual Plotly canvas width, range changes, normalization, detail dialog, map, optional radar, cache reload and failed requests. The automated unit tests also compile the inline application script.
- Runtime dependencies are pinned CDN assets. Browser verification needs network access to Bootstrap, Leaflet, Plotly, ARPAE and map tile providers. The Plotly basic bundle supports the scatter plots used here.
- `config.json` defines ARPAE station IDs, fallback URLs, dependencies, refresh interval (minimum 5 minutes) and stale-measurement threshold. Keep station IDs aligned with fallback URLs. Retain UTC instants internally and format displayed dates in Europe/Rome.
- A threshold exceedance is not an official territorial alert. Missing thresholds, null readings, stale observations and cached responses must remain explicit. Do not turn normalized levels into risk probabilities or sum levels across stations.
