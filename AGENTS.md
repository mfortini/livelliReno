# Project workflow

- This is a static dashboard. No build step, package installation or backend is required for deployment.
- Serve locally with `python3 -m http.server 8080 --bind 127.0.0.1` from the repository root. Opening `index.html` through `file://` does not support the configuration and GeoJSON fetches.
- Run regression tests with `node --test tests/*.test.js` (Node 18+). Check the shared module with `node --check dashboard-data.js` and whitespace with `git diff --check`.
- Homepage layout: map on the left on desktop, collapsed above the cards on mobile; no forecast panel on the homepage. Card rows follow `RenoPredict.rankNodes(config)` in descending rank, from upstream to downstream, using the same dependencies as the graph. Loading coefficients is not needed on the homepage.
- The station panel (`#map-container`, a plain div — no collapse) has two tabs: "Catena delle stazioni" (default) and "Mappa". The chain is `updateStationDag()`, a small inline-SVG DAG (top = upstream, bottom = downstream) built from `P.buildGraph(config)` and `P.rankNodes(config)` with clickable chips showing wrapped station name (max two lines), status color and latest level. Columns are fixed by `DAG_COLUMN` (0 = Reno left, 1 = centre/confluence, 2 = Samoggia right, unknown stations centre) so edges never cross; the name font shrinks 11→10 px if the columns still do not fit the panel. Chips scroll to the station card — the same action as a map-marker click. The Leaflet map initializes lazily only when the map tab is selected (`mapRequested`); radar visibility is gated by `panel-map` being shown, not by a details toggle. No graph library is required; keep it dependency-free.
- Browser verification: check widths 360, 390, 768, 1024 and 1440 px, actual Plotly canvas width, range changes, normalization, detail dialog, map, optional radar, cache reload and failed requests. The automated unit tests also compile the inline application script.
- Runtime dependencies are pinned CDN assets. Browser verification needs network access to Bootstrap, Leaflet, Plotly, ARPAE and map tile providers. The Plotly basic bundle supports the scatter plots used here.
- `config.json` defines ARPAE station IDs, fallback URLs, dependencies, refresh interval (minimum 5 minutes) and stale-measurement threshold. Keep station IDs aligned with fallback URLs. Retain UTC instants internally and format displayed dates in Europe/Rome.
- A threshold exceedance is not an official territorial alert. Missing thresholds, null readings, stale observations and cached responses must remain explicit. Do not turn normalized levels into risk probabilities or sum levels across stations.
